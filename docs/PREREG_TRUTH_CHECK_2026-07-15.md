## 1. 动机:一个具体的、方向明确的偏差嫌疑

`run_calibration_oos.py` 判定市场"是否已结算"用的是**自建近似**(`engine/data.py:81`):

```python
converged = ypx < 0.05 or ypx > 0.95      # 终值价收敛到 0/1 附近
past = end_date is not None and dates[-1] >= end_date
return converged and past
```

且**胜负也由终值价推定**(`run_calibration_oos.py:50`):`won_yes = term[1] > 0.95`。

2026-07-15 对照官方权威真值(Gamma `outcomePrices`)实测:
- 代理**判胜负不出错**(小样本 0 冲突);
- 但**静默丢弃**大量已结算市场——丢的正是**终值未收敛**的盘,即"市场到最后还看走眼"的那些。

**为什么方向致命**:本策略 = **买标价高的那一侧**。一个收在 0.60 却结算为反面的盘,正是"买热门方"的**亏损案例**。代理规则要求终值收敛才入样 → **系统性剔除本策略的亏损样本** → 净利被抬高。

即:嫌疑不是"数据不够多",而是**样本里没有该有的败绩**。这比样本浅更致命,且更便宜验证。

## 3. 数据完整性闸门(不通过则中止,不出结论)

**下标对齐闸门** (`verify_index_alignment`):库价与 API 必须指**同一侧**,否则胜负标签会反,整个测试作废。

背景:Gamma `outcomes` 实测仅 **54%** 是 `["Yes","No"]`,其余为 `['Long','Short']`/队名/党派名;而库中 10 万行**一律**标 `outcome='Yes'`——"Yes"是**误称**。真正的不变量是**下标 0 对齐**:库价 == `outcomePrices[0]` == `clobTokenIds[0]` 那一侧。本策略只做"买标价高的那侧",**与标签无关**,只要求价格与结算指同一侧。

- 判据:重叠≥4 天的市场中,`median|api−db| < median|(1−api)−db|` 的占比 **≥95%**,否则 `sys.exit`。
- 实测(部分数据):**99.8%** 通过。重叠≥3 天的 346 个市场 100% 对齐、偏差中位数 **0.0000**(逐位相等)。

**为什么不逐市场剔除"反向"的**:表面"反向"全部集中在**仅 1 天重叠**的盘(尤以当天打完、盘中剧烈波动的 ATP 网球盘为甚)。反向占比 1天≈4% → 2–3天≈1% → ≥4天≈0.2%,**随数据变多单调趋零 = 噪声特征**,而非系统性错位(若真错位,数据越多应越确信为反)。按"反向"剔除等于**剔掉波动最大的市场**,反而引入新偏差。故只校验全局不变量,不做个体剔除。
