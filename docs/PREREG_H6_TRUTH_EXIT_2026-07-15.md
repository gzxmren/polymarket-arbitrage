## 1. 先厘清一个事实(纠正一处此前的误判)

滚动验证速览(`scripts/pzero_review_digest.py:110`)读的是 **`+1d`** horizon,**不是** `resolution`:

| horizon | H6 数字 | 是否受"结算真值"污染 |
|---|---|---|
| **`+1d`**(滚动验证主力) | +10.95% | **否** —— 标在次日市价,不涉及结算 |
| `resolution` | +2.00% | **是** —— 标在"最后一张快照价" |

**故此前"H6 恰在风险区"的说法,对 `+1d` 不成立。** 两个 horizon 各有各的隐含假设,病灶不同,分别登记如下。

## 2. 测试 C1 —— `resolution` 口径:了结价用"最后一张快照",而非真实结算

**现状机理**(`engine/portfolio.py:78-86`):`horizon == 'resolution'` 时 `mark_price = ps.terminal()` = **我们最后一次拍到的快照价**,而非官方 0/1 结算。
- 对**已收敛**的市场(终值≈0/1),这与真实结算几乎等价 → 无害。
- 对**未收敛**的市场(实测占 **80%**),这等于**假设自己能在中间价、无成本地平仓**。真实持有到结算是没有卖出动作的(到期直接赔付),所以这个"免费中间价出场"是**凭空多出来的**。

**自变量:有且仅有 `mark_price` 的来源。**

| 维度 | 两臂 |
|---|---|
| 市场范围 | ✅ 同(均限于**有官方权威真值**的市场) |
| 信号、入场价、入场成本、容量、gas | ✅ 同 |
| 假设集 H0–H7、cutoff、红线 | ✅ 同 |
| **了结价** | ❌ **唯一变量**:`ps.terminal()`(最后快照) vs 官方结算(1.0/0.0) |

- arm B 的 `mark_price` = `outcome_price(resolved_yes, sig.outcome)`,即我方赢=1.0、输=0.0;`mark_date` = `end_date`。
- 下标对齐前提:库价 == `outcomePrices[0]` == `clobTokenIds[0]` 同一侧,已于 2026-07-15 实测(重叠≥4天的 2384 市场 **100.0%** 对齐)。沿用同一闸门,不达 95% 则中止。

## 3. 测试 C2 —— `+1d` 口径:平仓不付卖出滑点

**现状机理**(`engine/portfolio.py:115`):`gross = (mark_price − entry_price) / entry_price`,其中 `entry_price` **已扣**入场成本(`cost.entry_fill`),而 `mark_price` 是**裸中间价**——**卖出滑点为零**。
- 对 `resolution`(真到期赔付)= 正确,没有卖出动作。
- 对 **`+1d`** = **错误**:一天后要真卖,必须吃进盘口。探针实测卖出滑点 **120bps(均衡盘) ~ 770bps(贴边盘)**,与价格强相关。
- H6 无价格下限 → 会踩贴边盘(高滑点区);H7 有 0.20 下限 → 理论上受损较小。**这恰好也是对 H7 存在意义的一次独立检验。**

**自变量:有且仅有出场是否付滑点。**
- arm B:`mark_price_eff = cost.exit_fill(mark_price)`,滑点曲线**复用探针价格敏感中位曲线**(`run_h7b_price_sensitive.calibrate_curve("median")`),**不新造、不调参**。
- 其余(信号/入场/容量/gas/假设集/cutoff/红线)全同。
