## 0. 为什么要这份契约(血的教训)

13 轮迭代全部证伪,根因**不在策略,在数据采集的选择逻辑**:每日快照按"成交量前 2000 + 未关闭"采 → 系统性丢 **54% 冷门鲸鱼市场**、抓不到官方结算(见 [[data-collection-two-tier-truth-2026-07-22]]);自建"已结算"代理静默丢 80% 样本 —— 全是**与结果相关的筛子焊进了采集**(见 [[truth-source-bias-2026-07-15]]、[[c1-resolution-verdict-2026-07-22]])。重生不基于旧数据,**重定正确逻辑,采无偏数据,再往下走**。

## 1. 头号原则(地基)

> **采集时不施加任何"未来策略可能想改的过滤"。把原始记录整个接住;谁算大户 / 采哪些 / 多大算大,一律推迟到分析时。**

- 任何被迫舍弃(网络失败/下架/超限)**大声计数,不静默**。

## 2. 采集范围(结果无关的边界 —— 已敲定)

| 维度 | 决策 |
|---|---|
| 场馆 | **仅 Polymarket** |
| 工具 | **仅二元市场**(0/1 结算;多候选事件=二元集合,逐腿采) |
| 市场类别 | **排除"短周期高频加密盘"(5 分钟涨跌盘)**——市场类决策,非金额筛(§2.1) |
| 成交笔 | **宇宙内每一笔全采,不设金额/主体阈值** |
| 主体 | **不锁定"跟鲸鱼"**;采全体,让数据回答"该跟谁" |

### 2.1 为什么排除高频加密盘是"范围"非"结果筛"
实测全局流 **71% 是 5 分钟加密涨跌盘的高频机器人尘埃**(名义额中位 $4),29% 才是真实事件市场。这类盘是纯 HFT 价格竞速、5 分钟即焚,**无"知情交易者可跟随"语义**,与"观察知情行为找 edge"的命题**天生不同类**——如同"只二元""只 Polymarket"是范围界定。⚠️ 诚实标注:排除它=**事前假设那类盘无可跟 edge**;若要验证该假设须**单独立项**,不在本契约。

### 2.2 HFT 分类器(v1.1 正则:先宽后严,宁漏勿杀)
- **确定排除**(market_class=`hft_crypto`):`slug` 或 `title` 命中 `updown` / `up-or-down` **且** 命中 `5m` / `-5-?min` / 形如 `\d{1,2}:\d{2}\s?(AM|PM)` 的时段窗。
- **疑似**(打 `hft_suspect=True`,仍入库,分析默认排除):命中 `-1h-` / `hourly` 等其它短周期特征但不满足上条。
- 分类器命中规则、边界样例、抽检误分类率均留档;变更须记录。**宁可先只排最确定的 5 分钟加密盘。**

## 3. 采集架构:按市场轮询(不喝全局水管)—— 探针实证

**核心接口** `GET https://data-api.polymarket.com/trades`。探针(2026-07-22)实证:

| 事实 | 证据 | 架构含义 |
|---|---|---|
| 全局流极密 | 1000 条/27s → ~320 万笔/天 | 全局流不可回填、offset 只够 ~4 分钟 → 弃用 |
| **无时间窗参数** | from/after/start/end 全被忽略 | downtime 后无法按时间补采(全局流) |
| **`market=<cid>` 过滤生效** | 单市场 100% 匹配 | ✅ 逐市场采 |
| **单市场 offset 上限 ~1 万** | offset≤10000 OK,≥15000→HTTP 400 | 见下"回填限制" |
| **前向轮询安全** | 史上最大盘 Trump2024:1 万条覆盖选举日 ~8 小时 → 峰值仅 ~20 笔/分 | **30 分钟一轮即使巨盘也 ~600 笔 ≪ 1 万** |
| 单市场可回填 | 慢盘一次翻完全历史(样例 200 笔/18h) | 中小盘全历史可回填 |

**⇒ 架构(v1.2:Firehose 发现驱动,三层 + 兜底):**

1. **发现层(宇宙定义)**:周期性采样全局 `/trades`(每次取 5000~10000 条最新成交)→ 抽取 conditionId 去重集合 = "活跃事件市场"候选集。**无金额/排序截断,任何成交即现身**(冷热平等,补旧项目 54% 盲区)。用 §2.2 分类器当场剔除 hft_crypto。
2. **注册层(元数据按需)**:候选集中**不在本地注册表**的新市场,按需查 Gamma(`?slug=`)拿 clobTokenIds / outcomes / outcomePrices / 结算,写注册表。已注册直接复用缓存,**不再全量枚举**。
3. **采集层(逐市场全量成交流)**:对注册表中的活跃市场执行 `trades?market=<cid>` 慢轮询,保证每笔历史完整。
   - **不需 VPS**:单市场慢,本机 + 带补跑 systemd timer(`Persistent=true`,见 [[cron-suspend-miss-fix-2026-07-06]])即可扛 suspend。
   - **回填限制(诚实)**:>1 万笔的巨盘只能回填最近 1 万笔;中小盘(<1 万笔)全历史可回填。
   - **offset 溢出兜底**:单市场两次轮询增量逼近 1 万者压频 <5 分钟;极端峰值由 §7 `offset_overflow` 告警。
4. **兜底(可选,防休眠漏网)**:每日一次极低频 keyset 全量枚举(允许 30~60 分钟),仅**比对** Firehose 发现集 vs 全量开放市场、记录缺口计数,**不强制补齐,仅审计**。纯数学上 Firehose 发现对"有交易行为"的宇宙已完备(只在 downtime 期成交过一笔且此后再无交易的市场无价格序列可跟、对策略无价值;后续再成交即被发现并回填)。

## 4. 要落库的原始记录(逐流契约)

### 4.1 `trades`(核心,只增不改)+ token→下标解析器铁律
每笔成交一行,字段取接口原字段:`transaction_hash, proxy_wallet, condition_id, asset, side, size, price, timestamp`(成交时间=点位时刻锚点)、`ingested_at`(采集时刻,审计用)。

**🔴 token→阵营解析器(实测铁律,v1.1 核心修补):**
- **`outcomeIndex` 不可信**:实测 28/30 为垃圾哨兵 `999`,**丢弃不用**。
- **可靠映射**:把 `trade.asset` 在该市场 `clobTokenIds` 数组里**查位置** → 该下标即 outcome index(实测 30/30 定位成功)。
- **交叉校验**:`trade.outcome` 字符串标签须 == `outcomes[位置]`(实测 30/30)。⚠️ 标签常**不是** Yes/No(实测有 `FaZe`/`Astralis`/`Down`),故**按下标不按标签**。
- **"这侧赢没赢"** = `outcomePrices[位置]` 的干净 0/1(未结算为空)。
- **定位失败(asset ∉ clobTokenIds)→ 拒绝入库 + 计数**,绝不猜。

**去重(实测无 log_index/fill_index):**
- 自然元组去重 `(transaction_hash, asset, side, size, price, proxy_wallet, timestamp)`。此键正确去掉**重复轮询的再抓**。
- 残余:同一 txhash 内逐位全同的拆分单,接口层面**不可分辨**→被折叠。**统计折叠发生率并计数**(随机、无偏、可量化),不假装有完美主键。

**价格/成交量从 trades 派生**(某日 VWAP/末笔 = 价;当日 size 之和 = 量)→ **旧每日价格快照退役**(职能被涵盖且无偏)。

### 4.2 `markets`(宇宙注册表 + 权威真值)
`condition_id`(PK), `slug/title/event_slug`, `market_class`(§2.2), `start/end_date`, `closed`, **`token_id_0` / `token_id_1`**(按 clobTokenIds 下标存,供解析器,**非 yes/no 命名**), **`outcomes_json`**(标签数组), **`resolved_outcome`**(官方 `outcomePrices` 干净 0/1,未结算为空,结算后一次写入,不可改), `first_seen/last_polled`。
- 真值姿势:`&closed=true` + 强制 IPv4 + 只认干净 0/1(见 [[api-backfill-2026-07-15]])。
- **已关闭未结算的市场:轮询升频至每 5 分钟**(结算窗口窄,怕错过);**已结算 → 移冷存,不再轮询**。

### 4.3 容量/执行层(v1 **暂缓**,诚实标注)
盘口深度/真实滑点历史拿不到,只能向前实时探。trades 已含"已实现成交量/价"流动性信号,够 v1 发掘。盘口探测另立(沿用现滑点探针),不阻塞本契约。容量是 edge 之后的第二道门。

### 4.4 存储底座(v1.1 定案:DuckDB + Parquet)
- **分析引擎 = DuckDB**(列式,SQLite 语法,零部署;需 `pip install duckdb`,pyarrow 24.0 已装)。**选它的核心理由是 ASOF JOIN** —— 它是 §5"禁止未来函数"的**机械执行器**(SQLite 做不了)。
- **入库层 = append-only、按 `date(timestamp)` 分区的 Parquet 文件**,DuckDB 直接查(零 ETL)。**不可变文件本身即 §5 的 append-only 保证**,且规避 DuckDB 单写者锁。
- **⏳ 开放决策(唯一待你拍板)**:Parquet-first(我的推荐)vs 你原提的"SQLite 暂存→COPY 进 DuckDB"。Parquet-first 更贴 append-only、省双写;SQLite 暂存对"边采边改/事务"更熟。请定。

## 5. 点位时刻完整性(防未来函数 —— 第一天就保)

- **只增不改不删**:trades 落库不改;`markets` 元数据可更新,但 `resolved_outcome` 一旦写入不可改。
- **双时间戳**:`timestamp`(事件发生)与 `ingested_at`(我们何时知道)。分析须能还原"截至 T 时刻只知道什么"。
- **🔴 as_of 机械强制**:构建特征时,**禁止** `WHERE resolved_outcome IS NOT NULL` 式回溯打标;凡"截至交易时刻的历史特征"(如钱包滑动胜率)**必须用 DuckDB ASOF/LATERAL JOIN**,保证特征窗口截止时间 ≤ 交易 `timestamp`。这是纪律能否被代码强制的关键。

## 6. 发掘 / 验证纪律(放开假设空间的四道笼子 —— 缺一不可)

放开"找任何 edge"= 巨型多重比较机,四道笼子同锁:
1. **发掘/验证物理隔离(时间防火墙)**:只在时间在前的数据挖;候选须在"时间在后、挖时从未触碰"的数据再活一次。持续累积 → 时间产出永远新鲜 OOS。
2. **每个被提拔假设,验证前先预登记**(`docs/PREREG_*.md`)。
3. **经济合理性闸**:优先讲得出机理的;纯数据挖出、说不出为什么的,默认判噪声。
4. **诚实计数搜索空间**:试了多少组合 → 最优者为运气的概率。

## 7. 采对了吗?—— 自审判据(采集器内建,大声报数)

- **audit 心跳**:每小时落一条 `audit_heartbeat(total_markets_polled, http_4xx_count, rate_limit_hits, offset_overflow_count, dedup_collapse_count)`。**`offset_overflow_count>0` → 采集进程自动暂停 + 紧急通知**(防带病狂奔)。
- **宇宙覆盖闭环(v1.2:Firehose 发现驱动)**:覆盖缺口检测 = **"Firehose 出现次数 vs 注册表存在性"实时比对**。任何在 Firehose 采样中出现 ≥3 次、但注册表缺失的 conditionId,**必须触发告警并自动注册**(拉 Gamma 元数据入注册表)。注册时 Gamma 查询失败**必须重试 + 计数,不得静默丢弃该市场**。可选每日低频 keyset 枚举仅作审计比对(§3 兜底),不作主发现路径。
- **完整性/无静默丢弃/append-only 校验**:trades timestamp 序列无可疑大洞;网络失败/下架逐类计数;定期核 trades 无 UPDATE/DELETE、`resolved_outcome` 未被改。

## 8. 本契约**不**承诺什么(防越界)

- ❌ 采到数据 ≠ 有 edge。干净数据仍可能无 edge —— 那才是真·归零。
- ❌ 巨盘(>1 万笔)历史**只能回填最近 1 万笔**,更早不可得(§3)。
- ❌ 容量/执行历史不可得(盘口只能向前)。
- ❌ 不覆盖被排除的 HFT 加密盘(§2.1,须另立项)。
- ❌ 不替代发掘纪律:数据让链条**可信**,发掘仍须经济直觉 + 预登记。
