### 偏离一:窗口按**成交日**切,不按**官方结算时刻**切 —— 这是放宽

母单 §1 明文:「**市场归属窗 = 按其官方结算时刻**(结果无关的时间坐标),不按入场时刻、不按发现时刻」「一个市场只能进一个窗」。

**本单做不到,原因是数据里没有这个坐标**(2026-08-11 实测):

- 注册表 `markets` schema 没有"实际结算时刻"字段;`end_date` 是**计划**结束日,不是实际结算时刻。
- 唯一可推的替代是注册表快照夹逼(某市场在快照 A 时 `closed=False`、快照 B 时 `closed=True`)。实测:
  - 能夹出关闭窗口的市场 **78,804 个**;
  - 但夹逼区间**中位宽 57.6 小时**(p90 227.6 小时);
  - 且**在 2026-07-31 之前能确定已关闭的只有 457 个市场**。
- ⇒ 按母单字面执行,发掘窗只剩 457 个市场,**低于母单 G1 的 400/窗下限的边缘**,且验证窗几乎为空。**测不成。**

**替代措施**(实测支撑,不是口头保证):

1. 按成交日切窗(D = 07-22~07-31,V = 08-01~08-10)。
2. **验证窗剔除"该钱包在排名窗已交易过的同一市场"** —— 这才是按成交日切窗真正的危害:同一个市场只结算一次,却把输赢同时喂给排名和验证,凭空造出相关。实测这部分占验证窗成交的 **1.7%**(3,801,457 笔中的 62,831 笔),剔除代价极小。

**残留风险,明说**:不同钱包在两窗押同一市场,该市场的结算结果仍会同时进入两窗。这**不会**在钱包层面制造假的"个人持续性",但会制造**钱包之间的相关** ⇒ 由 §6 的比赛组分块 bootstrap 承担。

**本偏离接受"这是在放水"的默认质疑。** 若日后注册表补上实际结算时刻字段,本测试应按母单字面重跑。

## 4. 🔴 符号铁律:每笔成交的输赢怎么算

**这一节是本单最容易安静出错的地方,单列。**

2026-08-11 发现:`resolved_outcome` 这个字段名会骗人。它**不是**"赢家的编号",而是 **0 号结果的最终赔付值**。

**代码依据**(权威,`11-collector/discovery_service.py:355-359`):

```python
op = json.loads(m["outcomePrices"])
v = float(op[0])                       # ← outcomePrices[0] = 0 号结果的最终赔付
resolved = v if v in (0.0, 1.0) else None
```

**实测旁证**(独立于代码,防止代码与数据不符):取每个市场每个 `outcome_index` 的最后成交价 ——

| | 样本数 | 最后成交价 均值 | 中位 |
|---|---|---|---|
| `outcome_index == resolved_outcome` | 45,342 | 0.1183 | **0.02** |
| `outcome_index != resolved_outcome` | 57,806 | 0.9867 | **0.999** |

⇒ 编号"相符"的那一侧价格趋近 0(输),"不符"的一侧趋近 1(赢)。

### 判定式(脚本必须逐字实现)

```
win(idx) = resolved_outcome           当 idx == 0
         = 1.0 - resolved_outcome     当 idx == 1

dir      = +1  当 side == 'BUY'
         = -1  当 side == 'SELL'

每笔毛边际 edge_i = dir_i * (win_i - price_i)          # 单位:每合约的美元
每笔投入   cost_i = size_i * price_i
```

### 🔴 运行时自检(**脚本启动时必跑,不过则中止,不许降级继续**)

在真实数据上断言:

1. `median(last_price | idx == resolved_outcome) < 0.10`
2. `median(last_price | idx != resolved_outcome) > 0.90`

**理由**:若 Gamma 接口日后改变 `outcomePrices` 的含义、或采集器改了解析,上述读法会**静默反转**,而反转后的结果看着一样合理。这个断言是唯一能让"我没读反"这句话可复核的东西 —— 直接对应 CLAUDE.md 那一问:*「如果它现在就是坏的,我看到的会有什么不同?」*

**且此定义在代码中只允许存在一份**(单一函数,被所有分支调用)。⛔ 不许复制粘贴到多处 —— 那是 `11-collector` 已犯过 3 次的「照抄结构而不抽象」。

## 5. 自变量:钱包战绩怎么算

**主口径 —— 资金加权毛收益率**:

```
R(wallet, 窗) = Σ_i [ size_i * dir_i * (win_i - price_i) ]  /  Σ_i [ size_i * price_i ]
```

分子 = 该钱包在该窗所有成交按持有到结算计价的毛盈亏;分母 = 投入的本金。

**为什么用资金加权而不是每笔等权**:2026-06 的分层归因显示,等权算出来的"正格"**全部**是分母效应的幻觉(`[[stratified-findings-2026-06-08]]`)。资金加权是上次证伪所用的口径,可比。

**每笔等权口径同时计算,但只作旁证。两者结论冲突时,以资金加权为准。** ← 此优先级**现在**写死,不给事后挑选留空间。

**口径含义,明说**:本式假设每笔成交**持有到结算**,因此测的是**该钱包的方向判断对不对**,不是他实际赚了多少钱(他可能中途平仓)。对"跟随者持有到结算"这个用途,本口径是对的;对"复刻他的实际收益"则不是。

|---|---|---|

**幅度线为何是 0.5pp 而不是 1.5pp**(用户 2026-08-11 拍板,理由入档):

两类错的代价不对称。**假绿灯**的代价 = 白跑一趟第二关,几个小时。**假红灯**的代价 = 误杀方向三、转去做需要从零建盘口采集腿的方向二,**以周计**。⇒ 这一关红线该松,而**红线松,红灯才可信** —— 用 1.5pp 判红,"是不是标准定高了误杀了"这个质疑我无法自证;用 0.5pp 判红,这句质疑不成立。

这不违反母单 §5「🟢 才是风险区」:**门放松是为了让红灯站得住**;万一真亮绿灯,后面有 §8 两道坏数据自检 + 第二关等着,审视一点没减。

**显著性为何不一并放松**:一次只动一个自变量。幅度线已放松,显著性维持常规 2.5% 分位数。
