## 1. 动机:不是"混淆",是"问题问窄了"(外部效度)

C1 的自变量是"了结价口径"。2026-07-15 测 C1 时意外发现:换成官方真实结算后 H6 由 +2.81% → +34.06%,且**方向与预判相反** —— 原以为"最后快照"会像校准候选那样**抬高**收益,实测它一直在**压低** H6。

**⚠️ 一处必须先厘清的定性(2026-07-21 review 更正):** 原脚本 `run_h6_truth_exit_check.py` 的两臂(arm A 最后快照 / arm B 官方结算)**都跑在同一个 truth 受限宇宙** `prices_c1`(9161 市场)—— 见 `line 108 prices_c1 = {m: ps ... if m in truth}`,两臂共用。因此**口径这个变量在那个宇宙内已被正确隔离,+34% 是一个干净的口径效应,原测试没做错。**

真正的问题**不是**"两臂裹挟了未隔离的变量",而是**外部效度**:那个宇宙不能代表 H6 的原生总体。

- **代表性缺口(实测)**:C1 truth 宇宙 = 9161 市场 / 3186 信号;H6 原生全库 = **39953 市场 / 6052 信号**。前者是 `--universe candidates` 用**校准**入场规则(dte 1–14、cap≥1000、`0.02<px<0.98`、每市场首个合格点)圈的一个短周期偏斜子集,不是 `strategies/follow_whale.py::generate_signals` 的原生地盘。
- **一处存疑的结果相关性**:`0.02<px<0.98` **排除了"入场时已近成定局"的盘**。这些盘在原生宇宙里存在、且很可能在官方结算下表现不同 —— 排除它们本身可能是一次隐蔽的结果相关筛样本(见 `truth-source-bias-2026-07-15`)。
- **短周期主导佐证**:C1 宇宙内 H2(dte≤14)n=1783 逼近 H0 的 n=1906,H0/H2 在此几乎同义。

**⇒ 本单要回答的是:同一个口径效应,搬到 H6 原生总体上还成立吗?** 自变量仍只有"口径"一个;变的是**总体**(从校准候选池 → H6 原生宇宙)。这是一份新总体下的新结果,故 §0 所述"事前"对它重新成立。

## 3. 数据完整性闸门(不通过则中止,不出结论)

### 3.1 下标对齐闸门(沿用 `run_calibration_truth_check.py::verify_index_alignment`)
库价与 API 必须指**同一侧**,否则胜负标签会反、整个测试作废。判据:重叠≥4 天的市场中 `median|api−db| < median|(1−api)−db|` 占比 **≥95%**,否则 `sys.exit`。常数与函数 `import`,不复制。

### 3.2 结算缺失必须**出声计数**且**检验非结果相关**(本单最关键的一道闸)
H6 原生宇宙里,一个市场进入 arm B 的条件是"已 `closed=true` 且 `outcomePrices` 为干净 0/1"。凡因**未结算 / voided / 非 0-1 收盘**被丢弃的信号,必须:

1. **逐类打印计数**(未 closed / closed 但非 0-1 / lookup 失败),给出丢弃总占比。静默丢样本是本项目头号真凶(曾静默丢 80%,见 `truth-source-bias-2026-07-15`)。
2. **检验丢弃是否与结果相关**:用 arm A(最后快照,两臂都有)的净收益,对比"被 arm B 丢弃"与"被 arm B 保留"两组。
   - 判据:若两组 arm-A 净收益差 > 2%(资金加权),记 ⚠️ **选择偏差嫌疑**,arm B 的任何 🟢 一律降级为不可信,须进一步分层;
   - 理由:市场"是否已到期结算"应与"这笔跟鲸鱼交易赢没赢"**无关**(纯时间驱动);若两组收益显著不同,说明丢弃口径里藏了结果相关性,重蹈 80% 覆辙。

### 3.3 arm A/B 必须取**可标记交集**(2026-07-21 review 升级为硬闸)
**实测隐患**:原脚本两臂笔数**不等** —— `笔数 — C1: 2563 vs 2534`,差 **29 笔**(`h6_truth_exit_20260715.txt:9`)。根因:`_mark` 里 arm B 用 `end_date` 作守卫、arm A 用 `last-snapshot-date` 作守卫(`portfolio.py:100-108`),两臂各自漏进/漏掉不同信号 → **藏了第二个变量**。

故本单**不接受**"两臂各跑各的、笔数不等"。硬性要求:

1. 取两臂**都可标记**的信号**交集**作为唯一样本集(arm A、arm B 在交集上逐笔一一对应)。
2. **出声计数**:打印 `arm A 独有 / arm B 独有 / 交集` 三个数;若任一独有 > 交集的 5%,记 ⚠️ 并排查(可能守卫逻辑本身有结果相关性)。
3. 交集之外的信号一律不进任何一臂的分母。**不许** arm A 用全宇宙、arm B 用子集。§2 的"宇宙同"即指此。

### 3.4 已排除的嫌疑:`is_resolved` 的 80% 丢样本偏差**不污染本测试**(2026-07-21 核实)
读者会担心:本测试是否重蹈校准覆辙(`is_resolved()` 用价格收敛推定已结算,静默丢 80%)?**已核实:不会。**

- arm B(truth)**根本不调用** `is_resolved()` —— `resolved=True` 直接来自官方真值(`portfolio.py:93-103`);样本由 `truth.get(market) is None → None` 决定,即"有无官方结算",非"价格收不收敛"。
- arm A(terminal)**调用** `is_resolved()`,但只用于**写 `resolved` 标志位**(`portfolio.py:111`),**不筛样本**;`evaluate()` 也不按 `.resolved` 过滤(`run_h6_truth_exit_check.py:60-64`)。
- ⇒ 那个致命偏差在本测试的**两臂都不生效**。这是本测试与校准候选**根本不同**的地方,可放心。(§3.2 的选择偏差闸防的是**另一件事** —— 官方结算本身的缺失是否结果相关。)
