## 2. ✅ 已实测的结论(可以直接用,不必重做)

### 2.1 标的与结算

| 事实 | 值 | 证据 |
|---|---|---|
| 结算源 | 🔴 **Chainlink BTC/USD 60s TWAP,不是币安** | `resolutionSource` 字段;description 明写 "not according to any other sources or spot markets" |
| 结算规则 | end 时刻 60s TWAP ≥ start 时刻 60s TWAP → Up 赔 $1 | 官方 changelog:"price to beat 与 settlement price **都来自 TWAP feed**";15m 用 **60 秒 lookback** |
| 窗口 | `btc-updown-15m-<UTC起点>`,900 秒一窗,一天 96 个 | slug 实测 |
| **taker 手续费** | **`shares × 0.07 × p × (1−p)`**,**两条腿各付各的** | `feeSchedule` 字段 |
| maker 手续费 | **零**,另有 20% rebate | 同上(⚠️ rebate 规则未查,建议回测记 0) |
| negRisk | 我们的盘 **False** | Gamma 元数据 |
| 最小报价单位 | **随价位变**:p≈0.5 时 0.01,极值处 0.001 | 实测两个盘 |

### 2.2 三条路的状态

| 路 | 逻辑 | 实测 | 结论 |
|---|---|---|---|
| **同盘吃单套利**(ask_up+ask_down<1) | ✅ | **扣费后仅 0.26% 的时刻**(50天/378万行) | 🔴 **判死** |
| **5m–15m 跨窗口** | ✅ 最小赔付 1.0,中间区间赔 2.0 | 前提已验(每 15 分钟对齐,一天 96 次) | 🟡 **最有希望,机会频率没测** |
| **做市挂单** | ✅ | `bid+bid` 中位 0.98 ⇒ **95.57% 时刻有 2% 毛利** | 🟡 毛利非净利,单腿/逆选未测 |

### 2.3 关键数字

- **吃单成本** `ask+ask` ≈ **1.01~1.02** ⇒ 加 3.5% 手续费 ⇒ **结构性必亏**
- **挂单成本** `bid+bid` ≈ **0.98~0.99** ⇒ maker 零费 ⇒ **1~2% 毛利**
- **Chainlink 滞后币安 = 3 秒**(互相关峰值 r=0.999128;声称的 4–12 秒**被夸大**)
  ⚠️ 但**滞后存在≠能赚钱**:做市商也看币安且比我们快,报价已吸收这 3 秒
- **同盘套利日频**(50天数据,最优价口径):87.8 次/天,净边中位 0.821%
  ⚠️ 该统计假设"每次都抓得到",而**机会持续中位 0.00 秒**
- **首次延迟检验**:瞬时边 +1.537% → 延迟 150ms 后 **−5.430%**,存活率 **0%**(样本仅 2 次)

### 2.4 5m–15m 跨窗口的结构(还没测频率,但逻辑和前提都验过)

同 `endTime` ⇒ 两盘用**同一个结算价 F**,但 beat price 不同。
买 5m-UP + 15m-DOWN(当 `beat_15m > beat_5m`):
`F < beat_5m` 赔 1.0 | **`beat_5m < F < beat_15m` 赔 2.0** | `F > beat_15m` 赔 1.0
⇒ **最小赔付 1.0,成本 <1 即无风险**,且带"中间区间翻倍"的上行。
**对齐规律(实测 3/3)**:`15m 盘 slug 时间戳 + 600 = 对齐的 5m 盘时间戳`。

## 3. 🔴 踩过的坑(每一个都真实撞过,别再撞)

| # | 坑 | 后果 |
|---|---|---|
| 1 | `/book` 的 asks **降序**、bids **升序**,最优价在**数组末尾** | 用 `[0]` 取最优价会拿到最差价 |
| 2 | `price_change` 里 `size=0` 表示**该档消失** | 只认"更优价"会让盘口永远不更新 |
| 3 | CLOB WS 有**三种**消息:空确认帧 / `payload.data[]` 快照 / 单点更新 | 照文档示例解析会 `KeyError` |
| 4 | 选盘要选**正在交易窗口内**的 | 取 slug 最大的会拿到还没开盘的空盘 |
| 5 | 成本必须**走单簿**,不能用最优价 | 最优价只够买第一档那点量 ⇒ 系统性低估成本 |
| 6 | taker 费**两条腿各付** | 只算单边 = 少算一半 |
| 7 | `eventStartTime` 才是窗口起点,`startDate` 是**创建时间(差一整天)** | 取错时刻的 TWAP 当结算阈值,整个判断作废 |
| 8 | `negRisk` 必须从元数据读 | 硬编码 True 会下到**不同的交易合约** |
| 9 | Gamma **默认只回未关闭盘** | 查已结算的必须 `&closed=true`,否则静默返回空 |
| 10 | 机会必须按 **`edge_after_delay`** 判定 | 用瞬时边会把"已经消失的盘口"算成机会 |
| 11 | Polymarket WS 的 Chainlink 价与**网页同源** | 拿网页核对 WS = 自己核对自己;要独立验证得走 **Polygon 链上直读** |

## 5. ⚠️ 我的失误清单 —— 接手前请读,它决定哪些结论要打折

**同一天出现三次独立偏差,全部朝"更有机会"的方向**:

1. 交易成本用**最优价**算(应走整个订单簿)⇒ 所有成本被低估
2. 手续费只算**单边 1.75%**(实为两腿共 3.5%)⇒ 门槛被放松
3. 机会用**快照瞬间**的边判定(应延迟 120–200ms)⇒ 把消失的盘口算成机会

⇒ **凡是本文件里带"0.26%""87.8 次/天""0.821%"这类数字的,都是用①②口径算的,
   全部偏乐观,是上界。** 按 Grok 建议的走单簿口径重算,只会更少。

另外三次是工具本身出错(时区填错、`while read` 漏最后一行、探针放在基线快照之前),
都靠"对账数字对不上"才发现 —— **这也是为什么本文件强调覆盖率优先。**
