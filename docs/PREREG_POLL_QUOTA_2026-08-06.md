# 预登记单:轮询名额还能不能抬(`DEFAULT_POLL_LIMIT` 50 → ?)

**日期**:2026-08-06 **状态**:红线已写死,测量未开始
**规矩**:CLAUDE.md「先写判据再写代码」——**本单写完之前不许看任何测量结果**

---

## 0. 要回答的问题(只有一个)

**一轮 170 秒的时间闸内,实际能轮询多少个市场?**

`DEFAULT_POLL_LIMIT = 50` 这个常数来自冷启动年代的一句注释(「~11s/个」)。
今天实测轮询段 p50 = 73s、p90 = 171s(即 1.46 与 3.42 s/个)⇒
**网络差时 50 个刚好用满闸,但过半轮次只用掉 170 秒里的 73 秒**。

抬名额**不改变最坏周期**(闸还是 170s),所以它不动 540s 告警线那套推导。
唯一的问题是:抬了之后**真的能多采到市场吗**,还是名额刚好落在最贵的那种盘上、
被闸砍掉、白忙?

---

## 1. 为什么这件事值得测(病灶,实测)

- 每轮**注册进 ~90 个**新市场,**只轮询 50 个** ⇒ 进的比出的快近一倍。
- 后果:大量盘没被采过就关闭,掉进回填清扫的目标集(实测漏入 ~4,600/天)。
- `offset` 溢出(单市场攒超 10,000 笔被接口截断,超出部分**永久拿不回**)
  在 1,837 轮里发生过 **214 轮共 321 次**,最后一次 2026-08-04 06:30 ——
  **曾经在咬、目前没咬**。名额越紧、轮转一圈越久,它越容易再咬。

## 2. 自变量与固定量(一次只动一个)

| | |
|---|---|
| **自变量** | 每轮轮询的市场个数 |
| **因变量** | 单市场轮询耗时(墙钟秒) |
| **固定** | 代码版本(`4ef438c`)、`POLL_TIME_BUDGET_S=170`、`OFFSET_CAP=10000`、`PAGE`、代理隧道、同一次测量窗口内连续测完 |

**分层**(耗时的已知主因,必须分开量,不许混成一个均值):

- **A 增量层**:有 watermark(采过)⇒ 翻到追上上次即停
- **B 冷启动层**:无 watermark(一笔没采过)⇒ 从 offset=0 全量回填

混成一个均值会掩盖真相:轮转片里冷盘扎堆,而新鲜片几乎全是增量层。

## 3. 抽样规则(⭐防止"丢得与结果相关")

1. **抽样框** = 本次实测的 firehose 活跃集 ∩ 注册表 ∩ `closed=False` ∩ `market_class='event'`
   —— 即 `pollable` 的真实定义。用注册表全集会混入早已停摆的盘,量出来的冷启动成本不代表真实名额消耗。
2. 每层内**均匀随机**抽,不排序、不挑"成交量大/小的"。
   ⛔ 用任何与耗时相关的量筛样本(如"跳过看起来很大的盘")= 直接作废。
3. ⭐**两层交替抽取**(A、B、A、B…)。
   时间预算用尽时被砍掉的必须是**两层的尾巴**,不能是「便宜的全测完、贵的只测了几个」——
   那正是与结果相关的截断,会把成本系统性低估。
4. **超时/失败的样本照记不弃**:按实际耗时记入,并单独计数。
   剔掉慢样本 = 用与结果相关的变量筛样本(本项目 2026-07-15 栽过的那个坑)。
5. 全程**只读**:调 `poll_market` 取行、丢弃,不写数据湖、不动任何游标/水位线。
6. **给采集器让路**:开工前判、过程中每 10 个再判一次(与回填清扫同一条理由:抢同一条代理隧道)。

**样本量**:每层 ≥ 25 个(时间预算 240s)。达不到就如实报"样本不足",不许拿 5 个的均值下结论。

## 4. 判决表(结果出来之前写死)

记 `c_A`、`c_B` 为两层的 **p90** 单市场耗时(用 p90 不用均值:闸咬的是慢的那一侧)。

一轮的成本模型(`N` = 名额,`R` = 轮转片名额,`f` = 轮转片里冷盘占比):

```
cost(N, R) ≈ (N − R)·c_A  +  R·[ f·c_B + (1−f)·c_A ]
```

新鲜片按定义是"最近成交的",几乎必然采过 ⇒ 用 `c_A`。

| 条件 | 判决 |
|---|---|
| 解出的 `N_max`(令 cost = 170s)**≥ 60**,即比现在多 ≥ 20% | 🟢 抬到 `N_max`,并把富余名额优先给 `R` |
| `N_max` 落在 **[50, 60)** | 🟡 抬了几乎没用 —— **不改名额**,改去做「拆独立 timer / 降单市场成本」 |
| `N_max` **< 50** | 🔴 现在这个 50 已经**超发**了(闸每轮都在砍,只是没人看)⇒ 不但不能抬,还要查为什么 |
| 任一层有效样本 < 25 | ⛔ **不下结论**,补测 |

**红线(逐条,越一条就不能上线)**

- **R1 新鲜片必须占多数**:`R < N/2`(热门盘的保护;沿用 `test_poll_rotation.py` 已写死的上界)
- **R2 轮转一圈必须短于** `OFFSET_CAP / p99.9 成交率 = 10000/859 ≈ 11.6 小时`
  (逐字沿用 `test_poll_rotation.py` 里那条,不复制粘贴数字 —— 判据里 `import` 它)
- **R3 四闸声明值之和 < 540s 告警线**:`POLL_TIME_BUDGET_S` 不动 ⇒ 自动满足,但判据仍要跑
- **R4 抬名额后必须实测复核限流**:`rate_limit_hits` 若开始非零,立刻回退
  (更多请求 → 更可能撞 429,这是本次改动**唯一**可能让别处变坏的路径)

**⭐反自欺条款**:若 `N_max` 算出来很漂亮但依赖 `f`(轮转片冷盘占比)的某个乐观取值,
必须用**实测的 f**,且把 f 的来源写进结论。f 拿不到实测值 → 按最坏 `f = 1` 算。

## 6. 结果(测量后追加,不得改上文任何一个字)

**测量**:2026-08-06 12:20:34–12:24:12,代码版本 `4ef438c`,seed 20260806,
脚本 `11-collector/measure_poll_cost.py`。测量窗口内暂停了回填清扫(之后已恢复),
采集器让路检查全程无触发(`yielded=0`),预算未用尽(`cut=0`)⇒ **无截断偏差**。

抽样框:firehose 3000 笔 → 活跃 491 → pollable 387(**采过 246 / 从没采过 141**,
冷盘占比 **f = 0.3643**)。两层各测 40 个,均 ≥ 25 的下限。

| 层 | n | p50 | p90 | max | 单市场取回笔数 p50 / max |
|---|---|---|---|---|---|
| A 增量(采过) | 40 | 1.60s | 6.70s | 19.82s | 39 / 271 |
| B 冷启动(没采过) | 40 | **1.13s** | **7.07s** | 25.66s | 37 / 411 |

网络:93 次请求、13 次重试、重试耗尽 0、限流 0、offset 溢出 0。

### ⭐ 结论一:我写在单子里的那个阻塞假设是**错的**

本单第 1 节和交接单里都写着「冷启动层要从 offset=0 全量回填,**每市场成本不是常数**
(冷启动 11s/个正是这么来的)」,并把它列为动手前必须先量的 🔴 前提。

**实测:冷启动层不比增量层贵。** p50 反而更便宜(1.13s vs 1.60s),p90 基本持平
(7.07 vs 6.70)。原因也量出来了:冷盘的**中位取回笔数只有 37 笔** ——
绝大多数"从没采过"的市场根本没什么历史,一页就翻完了。
「11s/个」是冷启动**首日**(整个宇宙都没采过、含巨盘)的数,拿它推今天是错的。

⇒ **成本不是抬名额的障碍。** 这一条阻塞假设作废。

### ⛔ 结论二:本单的判决表**用不了** —— 模型本身写错了,不是数据不够

第 4 节的成本模型把一轮的耗时写成 **50 个市场各自 p90 之和**。这是错的:
50 个抽样之和会集中在 **50 × 均值** 附近,不会集中在 50 × p90 —— 除非它们同涨同跌。

照本单写死的公式算:`cost = 6.7N + 0.135R`,令 = 170s 得 **N_max ≈ 25 < 50** ⇒
按判决表该判 🔴「50 已经超发」。但这个数字与实测生产数据**直接矛盾**:
30 轮实测轮询段 p50 = 73s(50 个市场),而模型预测 p50 也该是 335s 量级。

真实结构是:**同一轮里各市场的耗时高度相关**(共用一条代理隧道)——
轮耗时由"这一轮网络好不好"决定,不由"抽到哪几个市场"决定。
所以正确的量是**整轮耗时的 p90**(实测 171s),而不是单市场 p90 的和。
