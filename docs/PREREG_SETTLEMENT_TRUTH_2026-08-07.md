## 1. 被检验的对象(真值是怎么来的)

`discovery_service.parse_market`:

```
resolved = float(outcomePrices[0])  当且仅当 closed==true 且该值恰为 0.0 或 1.0
```

即 **真值 = Gamma 的 `outcomePrices` 数组第 0 项**。
`resolved_outcome == 1.0` 的含义是"`outcomes[0]` 这一方赢了"。

**这条链上有三个数组必须下标对齐**:`clobTokenIds` / `outcomes` / `outcomePrices`。
成交流那边只验过 `clobTokenIds` 这一个,**另外两个的对齐从未被验证**。

## 3. 三个检验

### T1 下标对齐:真值方向与市场收盘价方向是否一致

**自变量**:每个已结算市场,取 `token_id_0` 的**最后 20 笔成交**的成交量加权均价,记作 P0
(不足 20 笔用全部;**一笔都没有的单独计数报出来,不许静默丢**)。

**判据量**:`disagree` = (真值为 1 且 P0 < 0.5) 或 (真值为 0 且 P0 > 0.5) 的比例。
P0 恰为 0.5 的单独计一类,不计入任一方。

**⭐更硬的那条:分层单调性。** 按 P0 分五层
`[0,0.1) / [0.1,0.3) / [0.3,0.7) / [0.7,0.9) / [0.9,1]`,
各层的不一致率必须**随 P0 远离 0.5 而单调下降**。
理由:价格越极端 = 市场越笃定,意外越少。若不单调,说明错的不是"个别意外",而是口径。

**判决表(先写死)**:

| 结果 | 判决 |
|---|---|
| 总体 disagree > 50% | 🔴 **下标反了**,全部既往结论作废,先修口径再谈其它 |
| 总体 disagree 10%~50% | 🟡 有系统性问题,须逐个查明再决定能不能用 |
| 总体 disagree ≤ 10% **且**分层单调 **且**最极端两层各 < 5% | 🟢 对齐成立 |
| 总体 ≤ 10% 但**不单调**,或极端层 ≥ 5% | 🟡 不给过 —— 总体数字好看掩盖了结构性错 |

**充足闸**:参与判定的市场数 < 5,000 则本测试不出结论(样本不足,不许硬判)。

### T2 缺失是否与结果相关

**对象**:拿不到真值的 6 个(已关闭无真值)+ 超期 3 个月以上未结算的 53 个。

**做法**:查它们在 Gamma 上的真实状态(是否 voided / 争议中 / 接口异常),
并比较这批的**结算前价格分布**与总体是否显著不同。

**判决表**:

| 结果 | 判决 |
|---|---|
| 这批的价格集中在 0.4~0.6(势均力敌) | 🟡 丢的是"最难判的那些",而那正可能是 edge 所在 —— 须在后续预登记单里当已知偏差登记 |
| 价格分布与总体无明显差异 | 🟢 随机缺失 = 噪声,量级 0.1% 可忽略 |

⚠️ 本条**不设 🔴**:59/57,005 = 0.1%,即使全偏也翻不动结论。它的作用是**登记**,不是否决。

### T3 记下之后会不会变(复查盲区有多大)

**做法**:从已记真值的市场里**随机抽 300 个**(随机种子写死 20260807,抽样脚本存档),
重新去 Gamma 查一遍,与库里的值逐个比对。

**为什么是 300**:若真实翻案率 p ≥ 1%,300 个里一个都不出现的概率约 5%
⇒ 全部一致即可以 95% 把握说 p < 1%。

**判决表**:

| 结果 | 判决 |
|---|---|
| 不一致 ≥ 1 个 | 🔴 真值会变而我们看不见 ⇒ 必须建定期复查机制,且既往结论要按翻案率打折 |
| 300 个全一致 | 🟢 暂不建复查机制,但**把这个盲区写进契约**(现状是连"我们不复查"这件事都没登记) |

## 4. 本测试**不能**回答什么(写在前面,防止事后夸大)

1. **不能证明真值绝对正确。** T1 验的是"真值与市场收盘价方向一致"。
   若两者**同时**错且同向(例如 Gamma 给的 `outcomePrices` 本身就错,
   而成交流的 asset 映射也错、方向相同),这个检验抓不到。
   要排除这种,得引入 Polymarket 之外的第三方结果源 —— 不在本次范围。
2. **不能回答"市场定价准不准"。** 不一致率里必然包含真实的意外结果
   (收盘价 0.9 最后输了),那是市场的性质,不是数据错误。
   本测试只能通过**分层单调性**把"意外"和"口径错"分开,不能把意外率本身降到 0。
3. **不能回答已被 `parse_market` 拒绝的市场怎么样。**
   非二元、缺 token 的市场直接返回 None,压根没进注册表 —— 那是另一个口径问题,另立。
4. **不回答结算时点准不准。** 只验结论(谁赢),不验"什么时候结的"。
   若后续策略依赖结算时点(例如持有到结算的资金占用),须另开一单。

## 我自己设计上的三个错(比评审意见更值得记)

1. **红线测的不是我想测的东西。** 「总体不一致率 ≤10%」实测约等于
   `E[min(P0, 1−P0)]` —— 只由这批市场的价格分布决定。
   完美校准的市场在 0.3~0.7 那层本来就该有三四成"意外"(实测 37.9%)。
   ⇒ 这条线只能抓"整体反转",抓不到"某一类翻转"(一个 10% 子集整个反转,
   总体会是 22.8%,分层单调性照样成立,判决表只会给一句没有指向的 🟡)。
2. **盯着 59 个,漏了 17,181 个。** 见下条。
3. **把便宜的检验说成昂贵的。** 第 4 节写"要引入第三方结果源,不在范围",
   而真正独立的源是 **Polygon 链上 ConditionalTokens 的 `payoutNumerators`**
   (决定实际赔付,Gamma 的 `outcomePrices` 只是展示镜像)—— 一次链上查询而已。
