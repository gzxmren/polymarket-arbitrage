一句话结论：当前证据与"实盘盈利"目标冲突。修数据、修 bug、补工程债都基本做完，但这些都不是赚钱的瓶颈—— 瓶颈是还没有任何一个策略通过"真金白银（资金加权）为正"的测试。继续做"修复类"工作不会让这个数字由负转正。

❌ 缺 支柱② 下单 / 执行能力

06-tools/trading/ 只有一个 README。整个系统是只读 / 建议性的：能监控、报警、回测，但没有一行下单代码。 实盘还需从零建：CLOB 私钥签名下单、成交回报、持仓对账、风控限额、熔断开关、密钥安全。

✅ 够 支柱③ 干净的数据底座

2026-06-06 实测：垃圾率 0.0% / 死空间 0.5% / has_activity 错标 0。但这从来不是赚钱的瓶颈。

2. "整个项目的修复"修到哪了？

  • 当监控 / 研究平台看：相当完整、能跑——分层清晰、回测引擎可用、鲸鱼分析有深度。修复类工作大头已完成，边际收益递减。
  • 当实盘盈利机器看：还在第 1 步原地踏步——先验证再投，而验证结果一直是"未通过"。

路是什么前提 / 风险

4. 推荐路线：2 为台、1 为目标（混合）

用户倾向"在 2 的基础上推进 1"。合理，但必须把路2 定位成"测量仪器"，不是"赚钱手段"。

4.1 为什么这个组合成立

  • 回测 ≠ 实盘：真实成交、滑点、薄市场冲击，正是资金加权回测在"估算"的东西。微仓实盘给的是地面真值。
  • 执行层早晚要建：用封顶+熔断的最小版先建，安全且提前还工程债。
  • 用真实（小额）实验迭代"找 edge"，比纯靠历史回测更接近实战。

4.2 必须先讲清的风险（别自欺）

  • edge 在薄市场：即便微仓也可能自己推动价格；
  • 等权 +52% 是彩票型（靠极少数大赢家）：几百刀、几十笔样本统计上证明不了 edge，且很可能在等到赢家前先连亏一串；
  • 执行层=真金白银+私钥签名+操作风险，不是写个脚本就完。
  • 结论：路2 阶段一的目的是"校准仪器 + 验证执行假设"，不是盈利。

4.3 分阶段 + 硬门槛（Go / No-Go）

阶段内容进入下一阶段的硬门槛
P0 离线（路1）把"精选 edge"打磨到资金加权 ≥0 的候选；选可执行薄市场子集至少 1 个候选 OOS 资金加权 ≥0
P1 影子盘不下真单，按实时盘口记录"若下单会如何成交"，对齐回测假设影子盘成交假设与回测偏差 < 阈值
P2 微仓实盘（路2 台）极小资金（先 $100~300）、单笔封顶、日亏熔断、人工确认每单N 笔后复盘：执行假设成立 且 未触发熔断
P3 谨慎放大仅当 P2 执行无偏差 且 资金加权期望仍为正，才小步加仓每步都要资金加权为正 + 风控达标

⛔ 绝对红线

任何阶段先设总资金上限和最大可承受亏损；先建熔断 / kill-switch 再下第一单；私钥/密钥按现有 .gitignore 隔离规范处理，绝不入库。

5. 回答："我们能否在 2 的基础上推进 1？"

能，而且推荐——但带三个前置条件：

  1. 先把路2 定位成测量仪器（校准执行假设），不是盈利来源；
  2. 路1 先在离线产出至少一个"资金加权 ≥0"的候选，再让路2 去实盘验证它（否则就是拿真钱去赌一个回测已知为负的东西）；
  3. 执行层从"最小封顶+熔断"建起，每阶段卡 Go/No-Go 硬门槛。

换句话说：不是"先建执行层去碰运气"，而是 离线把候选磨到不亏 → 用微仓真实盘验证它是不是真的不亏 → 才谈放大。

6. 建议的下一步（落地动作）

第 1 步是纯离线、零资金风险，可立刻开干；第 2 步起涉及真钱/私钥，需用户明确授权后再动。

  1. (P0，离线) "精选 edge 资金加权攻坚"：系统性扫参数/市场子集，看能否找到 OOS 资金加权 ≥0 的候选，产出候选清单+判决。
  2. (P1，离线) 若有候选，搭影子盘/纸面执行框架（读实时盘口、模拟成交、不下真单），对齐回测假设。
  3. (P2，需授权) 仅当 P0/P1 通过，才设计最小执行层 + 风控/熔断，微仓实盘。
