## 3. ⭐主判决量

只保留**跟单价 `p ≥ P_FLOOR`** 的成交信号,每个投 1 块钱,取**平均收益率**:

```
r = win / p − 1 ,  R = mean(r) ,  单位 %
```

**为什么砍掉 0.10 以下**:等额投入下买 0.01 赢了是 +9900%,
少数彩票中奖主导平均值 ⇒ V5b 实测零分布 p95 高达 **+9.04%**,功效闸直接失效。
`p≥0.10` 时收益率被限制在 10 倍以内,噪声底应当大幅下降。
⚠️ **这是预期,不是保证** —— 故功效闸仍放在所有红线之前,压不下来就仍判「无判决」。

## 4. 🔴 `P_FLOOR = 0.10` 的来历(不许事后调)

那是**在跑 V5b 任何数字之前**定的,理由是"10 倍以内杠杆" ⇒ **门槛本身没被结果污染**。

⛔ **本单不许试 0.05 / 0.15 / 0.20 再挑一个好看的。**
敏感性可以跑(§11 S1),但**只能用于解释,不能改判**。

## 5. 口径(两版、两臂,逐条相同)

1. 只用已结算、`resolved_outcome` 非空的市场
2. `win = (outcome_index != resolved_outcome)` ⚠️ 与字面读法相反;
   **必须 import `wallet_skill_v3.WIN_SQL`,不许再抄一份**(V5b 栽过)
3. 时间防火墙:信号与跟单成交都 `ts <= closed_time`
4. 排除刷单市场;只用 BUY
5. 信号 = 前 10% 钱包对某 `(市场, 腿)` 的**最早**买入(跨全体领先者取最早)
6. 跟单价 = 信号后 **Δ=5 分钟**的下一笔真实成交(同刻多笔用成交量加权均价)
7. 一个 `(市场, 腿)` 只跟一次
8. 钱包门槛:两窗各 ≥20 笔买入
9. 领先者排名沿用 V4 的**同格配对得分**(只用排名窗信息)

## 6. 🔴 判决版的**开跑硬门槛**(先写死,不到不许跑)

数据攒够之前跑 = 小样本噪声,跑了也不算。三条**全部**满足才许跑:

- 验证窗内**已结算市场 ≥ 20,000 个**
- 两窗各 ≥20 笔的**合格钱包 ≥ 8,000 个**
- 验证窗内 `p≥0.10` 的**成交跟单 ≥ 10,000 笔**

(依据:实测 7 天窗 ≈ 40,668 市场 / 9,907 钱包;取其约七成作为下限,留余量。)

⚠️ 前置依赖:时间防火墙侧表必须已覆盖验证窗 —— 它现在是**一次性脚本、已陈旧 3 天**,
本单配套给它加定时任务,否则新结算的市场没有结算时刻,判决版**跑不了**。
