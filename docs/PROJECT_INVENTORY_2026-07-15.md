# 第四部分:为什么还在收集数据?(既然全部策略都死了)

诚实回答:**因为数据是原料,策略是成品。成品全废了,不代表原料该扔。**

1. **价格快照**:`edge = p − m` 里的 **m**,任何未来假设都绕不开。断一天就永久缺一天 —— 历史数据**无法事后补拍**(这正是 07-15 花一小时回填的原因)。
2. **鲸鱼成交流(`changes`)**:跟单已死,但它是"谁在什么价位下了多大注"的**原始事实**。C1 立项要查的正是它。
3. **滑点探针**:它是**唯一**能回答"我们真能以什么价成交"的东西。它已经用一次证伪(杀死 H6/H7)证明了自己的价值 —— 任何未来策略都要过它这关。
4. **健康巡检 / 清理**:保证上面三样别在无人看管时悄悄烂掉。

**已停的都是"为特定死策略服务"的**(pzero 周复验、CLOB 记录器、离线监控引擎)。**还在跑的都是"与策略无关的原料层"。** 这条线划得很清楚。

# 第五部分:方法学 —— 真正的产出

13 次迭代,**0 个盈利策略**。但产出了一套可复用的纪律,已写入 `CLAUDE.md` 强制执行:

1. **前置工作项**:研究性结论**先写预登记单**、功能代码**先写测试**。红线先写、且 `import` 被检验对象自己的红线 —— 这是"我没放水"唯一**可验证**的办法。
2. **绝不可用与结果相关的变量筛样本/贴标签**。缺得随机 = 噪声(无害);缺得与结果相关 = 错误(致命)。**"数据不完整"从来不是根因,"用沾边的东西筛样本"才是。**
3. **一次只动一个自变量**,其余维度逐条列表确认相同。
4. **任何降级/剔除必须出声计数** —— **静默是真凶**(曾静默丢掉 80% 样本而一声不吭)。
5. **改共享引擎必须默认关闭 + 回归证明**(原版 vs 新版跑**同一份**数据)。
6. **🟢 才是风险区**:抬高收益的偏差吹不倒本来就趴着的结论 → 过去所有 🔴 证伪**反而更牢固**(它们是在被放水的情况下仍然亏);任何 🟢、尤其推翻既往证伪的 🟢,应受**更严**审视。

## 一个贯穿全程的母题

> **迭代 1**:"98% 垃圾"—— 判据错了(把成交流鲸鱼当垃圾),结论是反的。
> **迭代 12**:"+0.46% 净正"—— 判据错了(用价格收敛推定结算),结论是反的。

**同一个错误,隔了 6 周,以最贵的形式重演了一次。** 这就是为什么第 2 条被写成铁律,而不是"注意事项"。
