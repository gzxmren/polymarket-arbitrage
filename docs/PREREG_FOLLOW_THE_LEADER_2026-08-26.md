## 1. 动手前三问

**Q1 服务哪条需求?** 项目唯一目的是赚钱。
V4 证明了「这批钱包比同格其他买方买得便宜约 5pp」是**已验证的行为事实**。
本单问的是那句要命的追问:**这 5pp 是他们的,还是你能拿到的?**

**Q2 不做会怎样?** V4 的 PASS 会被误读成"找到了 edge"。
而一个"他买得便宜、你追不上"的信号,**在账面上永远好看,在账户上一分不赚**。
不测这一步,后面任何投入都建在一个没验过的跳跃上。

**Q3 怎么验证?** §6 功效闸(先跑先判)+ §7 红线 + §8 双臂判读,全部先写死。

## 2. ⭐定义检查(定义 vs 后果)—— 本单最关键的一节

- **要测的东西,一句话**:一条"看到某人买、我也买"的规则,照它下注,
  **扣成本后、样本外仍然赚**。
- **卡门槛的变量**:**跟单者的净收益** —— 用他**看到信号之后才可能拿到的价格**入场。
- **是定义本身吗?** 是。

⚠️ **「他们买完之后价格动不动」是后果,不是定义。** 价格动了但你追不上,等于没动。
- 拿掉"用信号之后的价格" ⇒ 变成拿**领先者自己的成交价**算,那 5pp 是他的不是你的;
- 拿掉"样本外、扣成本" ⇒ 是拟合。
- 反过来只留"信号之后的价 + 样本外 + 扣成本净赚" ⇒ **它就是 edge 本身**。

⇒ **主判决量必须是跟单者的成交价,不是领先者的,也不是价格变动幅度。**

## 3. 精确定义

### 3.1 领先者名单(样本外,复用 V4)

用 **D 窗**(结算时刻 < 边界 T)的 V4 同格配对得分排名,取**前 10%**。
排名只用 D 窗信息 —— 结构上拿不到 V 窗(V4 的 `rank_wallets` 只接受 D 窗成绩)。

### 3.2 信号与跟单价

- **信号**:V 窗内,某个前 10% 钱包对某个 `(市场, 腿)` 的**第一次**买入,时刻 `t`。
- **跟单价 `p_follow`**:该 `(市场, 腿)` 上,时刻 `>= t + Δ` 的**下一笔真实成交**的价格。
- **跟单收益**:`win − p_follow`(持有到结算,无出场择时问题)。

⭐`Δ` 是**信号延迟**:从别人成交到你能下单之间的时间。
- **主口径 Δ = 5 分钟**(一个不赶时间的实现能做到的水平)
- 敏感性:Δ = 1 / 15 分钟(15 分钟 = 我们采集器当前轮询间隔)

⚠️ 若在结算前找不到 `>= t + Δ` 的成交,则**该信号未成交**,不计入收益,
但**必须出声计数**(见 §9 漏斗)。静默丢弃是本项目的死因。

### 3.3 去重:一个标的只跟一次

同一个 `(市场, 腿)` 只取**最早**的那个信号。
理由:真实跟单者不会在同一个标的上因为 5 个人先后买入就买 5 次。
⚠️ 敏感性臂保留"逐信号"口径(§10 S1),但**不参与主判决**。

### 3.4 主判决量

`R_follow` = 所有已成交跟单的 **金额加权** `win − p_follow`,单位 pp。
金额 = `p_follow × size_follow`(你实际投进去的钱)。

## 4. 为什么必须有置换零分布(不是走形式)

2026-08-24 实测:**买方作为一个整体,普遍比自己付的价多赢 0.5~1.6pp**,横跨所有价位。
⇒ **跟任何人买,账面上都会显得赚。** 不设零分布,一定得出假绿灯。
⇒ 零分布 = 从合格钱包池里**随机**抽同样多的钱包当"领先者",跑完全相同的构造。

## 5. 口径(两臂逐条相同,只差 §8 那一个自变量)

1. 只用已结算、`resolved_outcome` 非空的市场
2. `win = (outcome_index != resolved_outcome)` ⚠️ **与字面读法相反**,已用末价独立验证
3. 时间防火墙:信号与跟单成交都必须 `ts <= closed_time`(硬线)
4. 排除刷单市场(`wash_markets.json`)
5. 只用 BUY(建仓侧;卖出在本平台语义是平仓,是另一个问题)
6. 边界 T = **2026-08-08 00:00:00 UTC**;D 窗定名单,V 窗测收益
7. 钱包门槛:两窗各 ≥20 笔(与 V4 相同)

# V5b 修订(2026-08-26,**在看到 V5b 任何数字之前**)

## 🔴 为什么改:V5 的仓位模型是错的

V5 §3.4 把 `R_follow` 定义为「按**跟单成交的规模**加权」。
**现实中没有人被迫按别人的规模下注** —— 你看到信号,是你自己决定投多少钱。

后果(实测):最大的 100 笔占总投入 **35%**、1000 笔占 67.9%,中位单笔仅 $5、最大 $76,147
⇒ 有效样本掉到几百,自举区间宽 22.7pp。
⭐**这不是"精度是物理极限",是仓位模型定错了。**

三种口径给出的答案差别很大,印证它不是小事:
逐笔等权 **−0.04pp** / 按股数 **−2.29pp** / 按成交规模 **−3.49pp**。

## V5b 的统计量(用户 2026-08-26 拍板:每个信号投固定金额)

每个成交信号投 **1 块钱**,在跟单价 `p` 买 `1/p` 股,持有到结算。

```
单笔收益率 r = win / p − 1        (赢 = 1/p − 1;输 = −100%)
R_follow    = 所有成交信号的 r 的**平均值**,单位 %
```

## ⚠️ 这个口径的已知弱点与强制配套(先写死)

低价下注收益率**极端不对称**(买 0.01 赢了 +9900%,输了 −100%)
⇒ **少数便宜的赢家会主导平均值**。

⇒ **强制同时报三个数,缺一不可**(任何只报其中一个的汇报都不算数):
1. **平均收益率**(主判决量)
2. **中位收益率** —— 典型一笔长什么样
3. **只看跟单价 ≥ 0.10 的子集** —— 收益率被限制在 10 倍以内,杂音小得多

并附「按跟单价分档」的表。**三个数不一致本身就是信息**(说明盈亏集中在某个价格区间)。

## 🔴 红线(用户 2026-08-26 拍板,跑数前写死)

换算依据:在 0.5 附近的价格上,**1 个概率点 ≈ 2% 收益率** —— 与 V3/V4 的 1pp 门槛同源。

| | 取值 |
|---|---|
| **功效闸** `MDE_MAX_RETURN` | 置换零分布 p95 **≤ +2.0%**;超过则判「无判决」,⛔不许报 FAIL |
| **A · 置换** | `R_follow` > 零分布 p95 |
| **A0 · 绝对下限** | `R_follow` ≥ **+1.0%**(未建模手续费的安全边际) |
| **B · 稳健** | 自举 2.5% 分位 > 0(按**市场**聚类重抽) |

## 同时修掉的一个口径瑕疵

原实现在「同一时刻多笔成交」时按**价格最低**那笔取跟单价 —— 那是白送跟单者一个更好的价。
已改为该时刻**全部成交的成交量加权均价**(中性),并补了 SQL↔Python 等价性判据。

## 不变的部分

分窗、时间防火墙、排刷单、只用 BUY、一个标的只跟一次、Δ=5 分钟、
两臂(全部市场 / 两腿配平市场)、置换零分布必须有(理由见 §4)、判读规则形状、
以及「红了不等于他们没本事,是那 5pp 你拿不到」这句含义 —— 全部沿用 V5。

⇒ 按 §6 明令**不出判决,且不许报 FAIL/证伪**。

## ⭐ 三个必报的数把机制说清楚了(这是本单最有价值的产出)

- **中位 −100%** ⇒ **跟单的典型结果是本金归零**,超过一半的跟单一分不剩。
- **平均为正**,但正的部分全靠少数便宜的赢家撑着(等额投入下,买 0.01 赢了是 +9900%)。
- **只看 p≥0.10(占绝大多数,3.0 万 / 2.0 万笔)⇒ 贴着零**(−0.064% / +0.004%)。

⇒ 只能读成一句话:
> **跟单的全部"收益"来自极少数低价彩票中奖;在正常价格区间上,它不赚不亏。**

⚠️ 这**不是定论** —— 功效闸没过,精度不足以排除它其实是正的(自举下界仍为负)。

⭐ 顺带解释了 V5 那次 −5.71pp:那个负值同样是被少数大仓位主导,不是普遍现象。
两次口径看似矛盾,机制其实一致 —— **都是被少数极端样本主导**。

## 🔴 主判决量选错了(诚实记账,但**不改本单判决**)

我预见到了低价杠杆这个弱点(所以强制配套三个数),但**没料到它会大到让功效闸失效**:
等额投入把低价彩票的杠杆放大,随机挑一批人也可能撞上几个百倍赢家
⇒ 零分布 p95 从 V5 的 4.16 涨到 **9.04**。

真正稳的是 **`p≥0.10` 子集**那个数(n=3 万、两臂都贴零)。
⛔ **但它是配套报告项,不是主判决量,不许拿它翻案** —— 那就是看到结果后改标准。
⇒ 本单判决维持 NO_VERDICT;若要把它立成主判决量,**必须另起一单、重走需求→设计→编码→review**。
