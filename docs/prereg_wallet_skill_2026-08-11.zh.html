§0

顶部声明:相对母单的两处偏离

母单第 7 条要求:子单只能加严不能放宽;任何放宽必须在顶部显著标注并说明理由,并接受「这是在放水」的默认质疑。以下两处照办。

偏离一 · 窗口按成交日切,不按官方结算时刻切 —— 这是放宽

母单第 1 条明文:「市场归属窗 = 按其官方结算时刻(结果无关的时间坐标)」「一个市场只能进一个窗」。

本单做不到,原因是数据里没有这个坐标。以下为 2026-08-11 实测:

  • 注册表没有「实际结算时刻」字段;end_date 是计划结束日,不是实际结算时刻。
  • 唯一可推的替代是注册表快照夹逼(某市场在前一次快照 closed=False、后一次 closed=True)。
夹逼法的实测结果数值
能夹出关闭窗口的市场78,804 个
夹逼区间宽度 · 中位57.6 小时
夹逼区间宽度 · p90227.6 小时
2026-07-31 之前能确定已关闭的市场457 个

按母单字面执行,排名窗只剩 457 个市场,已在母单充足闸 400/窗 的边缘,而验证窗几乎为空。测不成。

替代措施(实测支撑,不是口头保证):

  1. 按成交日切窗:排名窗 07-22~07-31,验证窗 08-01~08-10。
  2. 验证窗剔除「该钱包在排名窗已交易过的同一市场」。这才是按成交日切窗真正的危害——同一个市场只结算一次,却把输赢同时喂给排名和验证,凭空造出相关。实测这部分占验证窗成交的 1.7%(3,801,457 笔中的 62,831 笔),剔除代价极小。
残留风险 · 明说

不同钱包在两窗押同一市场时,该市场的结算结果仍会同时进入两窗。这不会在钱包层面制造假的「个人持续性」,但会制造钱包之间的相关 ⇒ 由第 6 条的比赛组分块 bootstrap 承担。

本偏离接受「这是在放水」的默认质疑。若日后注册表补上实际结算时刻字段,本测试应按母单字面重跑。

偏离二 · 本单只做毛利层,母单 R1(净收益)留空不填

母单第 4 条顺序铁律:「先看毛偏差能否覆盖成本;毛利层不成立就到此为止」。本单就是那一步,因此不计交易成本、不计信号延迟。

由此推出一条必须写在最显眼处的结论

本单即使全绿,也不构成母单意义上的 🟢,更不是「发现了 edge」。最多只能说:毛利层没被证伪,有资格进第二关。第二关(加 15 分钟信号延迟 + 价格敏感成本 + 出场票价)才对应母单 R1。

写这一段是因为过往真实事故:结论在传递中被逐级「升格」。本段是防呆,不是谦辞。

§1

假设

H_W(钱包判断力持续性):存在一批钱包,其方向判断的准确度在一段时期内稳定优于市场标价;该优势可由前一时期的战绩识别,并延续到后一时期。

为什么自变量是「算得对」,不是「钱多」

2026-06 的「跟鲸鱼」证伪筛的是资金规模(谁下注大),本单筛的是判断正确率(谁算得对)。这是两个不同的自变量,前者被证伪不蕴含后者被证伪。

但先验依然差

跟鲸鱼的资金加权收益率是 −4~−5%。换了自变量不等于会通过,当年那些看着为正的格子后来查明全是分母效应的幻觉。

理论依据(方向先于数据钉定)

方向一(纯价格偏差)已于 2026-08-10 🔴 关闭,深层原因是:公开标价人人可算,真存在的偏差就会被抢空。方向三与方向一是同一件事的两个信息层级——加上「是谁在买」这一层非公开信息之后,edge 才可能存活。本单检验的正是这一层信息是否真的携带信号。

§4

符号铁律:每笔成交的输赢怎么算

本单最容易安静出错的地方

resolved_outcome 这个字段名会骗人。它不是「赢家的编号」,而是 0 号结果的最终赔付值。按字面读会让每一笔盈亏的符号翻转,而翻转后的结果看着一样合理,不会有任何东西报错。

代码依据(权威)

11-collector/discovery_service.py:355-359

op = json.loads(m["outcomePrices"])
v = float(op[0])                       # ← outcomePrices[0] = 0 号结果的最终赔付
resolved = v if v in (0.0, 1.0) else None

实测旁证(独立于代码,防止代码与数据不符)

取每个市场每个 outcome_index 的最后成交价:

样本数最后成交价 均值中位
outcome_index == resolved_outcome45,3420.11830.02
outcome_index != resolved_outcome57,8060.98670.999

编号「相符」的那一侧价格趋近 0(输),「不符」的一侧趋近 1(赢)。两条独立证据一致。

判定式(脚本必须逐字实现)

win(idx) = resolved_outcome           # 当 idx == 0
         = 1.0 - resolved_outcome     # 当 idx == 1

dir      = +1                         # 当 side == 'BUY'
         = -1                         # 当 side == 'SELL'

每笔毛边际  edge_i = dir_i * (win_i - price_i)   # 单位:每合约美元
每笔投入    cost_i = size_i * price_i
运行时自检 · 脚本启动必跑,不过则中止,不许降级继续

在真实数据上断言:

  1. median(last_price | idx == resolved_outcome) < 0.10
  2. median(last_price | idx != resolved_outcome) > 0.90

理由:若上游接口日后改变 outcomePrices 的含义、或采集器改了解析,上述读法会静默反转。这个断言是唯一能让「我没读反」这句话可复核的东西——直接对应那一问:如果它现在就是坏的,我看到的会有什么不同?

且此定义在代码中只允许存在一份(单一函数,被所有分支调用)。不许复制粘贴到多处——那是 11-collector 已犯过 3 次的「照抄结构而不抽象」。

§5

自变量:钱包战绩怎么算

主口径 —— 资金加权毛收益率:

R(wallet, 窗) = Σ_i [ size_i * dir_i * (win_i - price_i) ]
                ───────────────────────────────────────────
                Σ_i [ size_i * price_i ]

分子 = 该钱包在该窗所有成交按持有到结算计价的毛盈亏;分母 = 投入的本金。

为什么用资金加权而不是每笔等权:2026-06 的分层归因显示,等权算出来的「正格」全部是分母效应的幻觉。资金加权是上次证伪所用的口径,可比。

优先级 · 现在写死,不给事后挑选留空间

每笔等权口径同时计算,但只作旁证。两者结论冲突时,以资金加权为准。

口径含义,明说:本式假设每笔成交持有到结算,因此测的是该钱包的方向判断对不对,不是他实际赚了多少钱(他可能中途平仓)。对「跟随者持有到结算」这个用途,本口径是对的;对「复刻他的实际收益」则不是。

§6

判决 主判决唯一,现在钉死

  1. 在排名窗 D 上,对通过第 3 条全部条件的钱包按 R(wallet, D) 降序排名。
  2. 取前 10%(约 1,002 个钱包)记为「高手候选组」。
  3. 计算该组在验证窗 V 上的组合层面资金加权毛收益率 R_V(该组所有成交合并算一个数,已剔除第 0 条的跨窗同市场泄漏)。

幅度线为何是 0.5pp 而不是 1.5pp

用户 2026-08-11 拍板,理由入档。两类错的代价不对称:

错法后果代价量级
假绿灯白跑一趟第二关,在那里被打死几小时
假红灯误杀方向三,转去做需要从零建盘口采集腿的方向二以周计

所以这一关红线该松。而红线松,红灯才可信——用 1.5pp 判红,「是不是标准定高了误杀了」这个质疑我无法自证;用 0.5pp 判红,这句质疑不成立。

这不违反母单「🟢 才是风险区」

门放松是为了让红灯站得住。万一真亮绿灯,后面有第 8 条两道坏数据自检 + 第二关等着,审视一点没减。显著性那一头不一并放松——一次只动一个自变量。

  1. 坏数据自检 P1 / P2 —— 判据自己先过体检。未亮红则立即停工修判据,不许去看真实结果。
