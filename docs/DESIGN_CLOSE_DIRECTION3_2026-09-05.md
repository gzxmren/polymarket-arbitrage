## 1. 需求(三问)

**服务哪条需求**:方向三判决已出(2026-09-04,`NOT_FOLLOWABLE`)。支撑它的事件盘采集
每天仍在灌入约 50 万笔,而**没有任何活着的方向需要「新增」的事件盘成交数据**
(路一用已有历史;BTC 方向要的是完全不同的数据)。资源应转向唯一活着的新方向。

**不做会怎样**:采集器继续每 10 分钟跑一轮,消耗运维注意力(每次开工体检、看门狗告警、
周期耗时监控、反复发作的网络故障 —— 08-04 / 08-22 两次事故都是它),
而产出**没有任何消费者**。这正是本项目「信号必须有读取者」那条规矩的反面。

**怎么验证**:停完之后 ①全量判据仍零红 ②`systemctl --user list-timers` 里不再出现这 6 个
③本机与仓库两处配置一致 ④停采时刻已落盘且指得到。

### ⛔ 明确不做什么(边界)

| 不做 | 理由 |
|---|---|
| **不删数据湖(2.0GB)** | 零成本;路一若做要用它;删了不可逆 |
| **不删 V6 代码** | 归档 = 加作废注记,**不是**删文件。它是「这个方向怎么被否掉的」完整记录 |
| **不删 `deploy/systemd/` 里的 unit 文件** | ①判据在守它们(`test_daily_digest.py:271` 断言部署文件存在、`test_cycle_budget.py:92` 断言 timer 间隔匹配预算)⇒ 删了会红 ②保留 = 保留可逆性 |
| **不删任何判据** | 全量 1,145 条跑完仅 27 秒,零成本;路一若做立刻要用 |
| **本步不改造 slippage-probe** | 它要变成 BTC 方向 V1 的探针,那是**另一个自变量**,该单独一步单独验(CLAUDE.md 铁律 1) |

## 2. 设计

### 2.1 停哪些(6 个 timer,一次性一起停)

⚠️ **必须一起停,不能只停主采集器** —— 看门狗 `collector_watchdog.py:285`
(`if not _timer_active(TIMER_UNIT)`)会因采集器 timer 停而**每轮报红**,
日报会推全 0 的数字。只停一个 = 制造告警洪水。

| timer | 为什么停 |
|---|---|
| `polymarket-rebirth-collector` | 主采集器。服务的方向(三)已判死 |
| `polymarket-collector-watchdog` | 只服务采集器;不停会每轮报红 |
| `polymarket-backfill-closed` | 补采集器漏掉的市场;采集器停即无意义 |
| `polymarket-market-times` | 侧表**活已干完**(覆盖 99.9915%,只剩 14 个 Gamma 永远查不到的);现在只是空转 + 每次追平必响两声假警报(欠账 12) |
| `polymarket-daily-digest` | 采集器停后日报数字全 0 |
| `polymarket-slippage-probe` | **H6 遗留,H6 已于 2026-07-15 证伪 ⇒ 已白跑近两个月**,产出无人读。⚠️ 它的 `walk_book_buy()` 是 BTC 方向 V1 要的能力,**代码保留**,等 V1 改造后再重新开 |

### 2.2 怎么停

```
systemctl --user disable --now <timer>
```
⛔ **不许只用 `stop`** —— `stop` 只停当前,机器重启后 enabled 的 timer 会复活。

### 2.3 怎么保证可逆(这是本设计的核心)

🔴 **本节第一版论证是错的,已整段重写**(设计 review 打回,见 §3)。

#### 停采的真实代价(2026-09-05 重测,全部跑出来的)

| 类别 | 能不能补回来 | 依据 |
|---|---|---|
| 已知市场,笔数 < 1 万(**占 99.92%**) | ✅ **可完整回填** | 湖内 274,783 个市场笔数分布:中位 **11 笔** / p90 243 / p99 1,668 |
| 已知市场,笔数 ≥ 1 万(**213 个**) | ⚠️ 只能补**最后 0.2~40.8 天**(中位 2.1 天) | 15 个已结算巨盘实测;`offset` 上限 1 万笔 |
| **停采期间新诞生的市场** | 🔴 **100% 永久失明** | 见下 |

**按份额算的上界**:那 213 个巨盘占全湖**笔数 14.71%** / **名义额 9.40%**
(它们也能补回最后一段,所以这是**上界**不是实际损失)。

#### 🔴🔴 真正不可逆的是「新生市场失明」,不是巨盘补不全

新市场的**唯一**发现路径是 `discovery_service.py::sample_firehose()` —— 对**当下**的全局成交流
采样、抽出 condition_id 再查 Gamma 写入 registry。**它只在采集器运行时执行。**
已核实:`backfill_closed_markets.py::load_targets()`(第 103 行)只从 registry 取目标;
`backfill_market_times.py` 同理;**全项目没有任何按日期/分页枚举 Gamma 全部市场的路径**
(在 `11-collector/` 里 grep `markets?limit` / `order=startDate` / `order=createdAt` 零命中)。

⇒ 停采期间被创建、交易并结算的市场,**我们连它的 condition_id 都不会有**。
`offset` 能回溯多久对它毫无意义 —— 那条论证的前提是「已经知道要查哪个市场」。

⛔ **这条代价是已知且被接受的**,不在任何「补得回来」的说法范围内。
⭐ 摆过的备选:留一个极低频的 **discovery-only** 轻量任务(只采样 firehose 记 cid、不采成交)
能保住这个能力。**本设计不做** —— 用户 2026-09-05 明令「彻底 close」「资源完全集中到 BTC」,
而它服务的是「将来若回头做事件盘 → 且那时需要这段历史」这个三重假设,按「离赚钱几步」不值当。
**这是有意识的取舍,不是遗漏。**

#### 可逆性靠这三件东西

1. **unit 文件两处都保留**(本机 + `deploy/systemd/`)⇒ 恢复只需 `enable --now`
2. **停采时刻与湖基线落盘**(§2.4),将来回填从那里读该补哪一段
3. **仓库里留醒目记号**:`deploy/systemd/README.md` 顶部加警告,防止将来照 README
   手工重装时又把它们装回来(本项目踩过「配置两份副本」的坑)

### 2.4 ⚠️ 停采之后必须写进文档的一句话

> **停采之后「没有告警」是因为它没在跑,不是因为它健康。**

这条单独列出来,因为它正是本项目通篇在防的那个形状(静默失败:一切正常但产出为 0)。
将来任何人(包括我)看到「6 个 timer 全绿 / 看门狗没报警」时,
必须先问「它们还在跑吗」,而不是当作健康。

### 2.5 V6 代码归档方式

在四个文件(`follow_the_leader` / `wallet_skill_v3` / `wallet_skill_v4_matched` /
`wash_trading_detector`)**顶部加作废注记**,内容含:判决日期、判决结论、
⭐**验证窗已烧掉**(只跑一次、已看过 ⇒ 任何后续方案不许拿同一段数据当干净检验)。

⛔ **不移动文件** —— 移动会破坏 import(四者互相引用 + 7 个判据文件引用)。


#### 🔴 注记写法必须钉死(设计 review 实测拦下的坑)

四个文件**全部**在 module docstring 之后紧跟 `from __future__ import annotations`
(分别在第 **27 / 28 / 34 / 33** 行)。Python 规定 `from __future__` 之前只允许
「module docstring + 注释/空行」,**不能有第二条独立的字符串语句**。

⛔ **不许在已有 docstring 之外再起一段三引号块** —— 实测报
`SyntaxError: from __future__ imports must occur at the beginning of the file`,
一次炸掉四个文件 + 六个引用它们的判据文件(pytest collection error)。

✅ **只许这两种写法**(均已实测通过):
1. **`#` 注释行**(推荐),放在 shebang 之后、原 docstring 之前;
2. 把注记文字写进**已有 docstring 内部**(同一对三引号里),不新起字符串字面量。

⚠️ 措辞注意:`wash_trading_detector` 的「单钱包占比检测」逻辑在 BTC 方向可能还要复用,
注记别让「已作废」三个字劝退了对这段逻辑的重用。

### 2.6 被否掉的备选

| 备选 | 为什么否 |
|---|---|
| 删掉 `deploy/systemd/` 里的 unit 文件 | 判据在守它们会变红;且删了就不可逆 |
| 只 `stop` 不 `disable` | 机器重启后复活,等于没停 |
| 只停主采集器,留看门狗「以防万一」 | 看门狗会每轮报红 ⇒ 告警洪水 ⇒ 真信号被淹(降噪是可靠性工作) |
| 把 V6 四个文件移进 `archive/` 目录 | 破坏 import 与 7 个判据文件 |
| 顺手把 slippage-probe 改造成 V1 探针 | **同时动两个自变量** ⇒ 出问题无法归因。单独一步 |
