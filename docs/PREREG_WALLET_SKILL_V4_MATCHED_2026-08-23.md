## 3. ⭐新估计量:同一市场、同一条腿内部的**配对价差**

### 3.1 为什么outcome会被约掉(这是整个设计的支点)

在一个市场的**同一条腿**上,所有买家拿到的结算结果 `win` 是**同一个数**。
故任意两个买家的 edge 之差:

```
edge_X − edge_others = (win − p_X) − (win − p_others) = p_others − p_X
```

**`win` 完全约掉。**⇒ 剩下的只有价格差,而价格在 [0,1] 内、
同一市场同一条腿内部的离散度远小于"押中/押不中"这个二元结果的离散度。
**这就是降方差的来源,不是靠加样本。**

### 3.2 无信息的"早买型"钱包会不会被误判成有本事?

不会,而且是对称地不会:
- 早买**最终赢**的腿 ⇒ 买得便宜 ⇒ 配对价差为正
- 早买**最终输**的腿 ⇒ 买得贵(晚买的人只花 0.05)⇒ 配对价差为负

无信息则两者按基础率抵消,期望为 0;**只有真的"看得比别人早/准"才会净为正。**

### 3.3 为什么**不**按时间分桶

按时间分桶会把"比别人早看出来"这件事**控制掉**,只剩微观执行差异 ——
而"早"恰恰是信息的表现形式。⇒ 主口径**不分桶**。
分桶版本作为敏感性臂(§10),用来回答"多少来自时机、多少来自执行",**不参与主判决**。

### 3.4 精确定义(⚠️ 含一次**跑数之前**的修订,见下)

对每个「市场 × 腿」单元格 c 与钱包 w:

```
O(w,c) = 该格内**除 w 之外**所有 BUY 成交的股数加权平均价      ← 留一法
p̄(w,c) = w 在该格的股数加权平均买价
s(w,c) = O(w,c) − p̄(w,c)
```

钱包 w 的窗内得分 = 各格 `s(w,c)` 按 **w 在该格的买入金额**加权平均,换算成 pp。

> ### 🔴 修订记录(2026-08-23,**在跑出任何数字之前**)
>
> 本节初稿写的是 `s(w,c) = P_c − p̄(w,c)`,其中 `P_c` 是**含 w 自己在内**的全格均价。
> 那是错的:一个在某格里占主导的钱包,`P_c` 会被它自己拉过去 ⇒ 得分被**机械地压向 0**,
> 不是因为它没本事,而是因为**它在跟自己比**。占比越高压得越狠 ⇒ 与"仓位大小"系统性相关,
> 正是本项目明令禁止的那种偏差。
> ⇒ 改为**留一法**(排除 w 自己的成交)。
> ⚠️ 此修订发生在**看到任何结果之前**,故不违反"结果出来后不许改标准";
> 但按母单要求必须留痕,不许悄悄改。

⚠️ 只用 BUY。SELL 在本平台语义是"卖掉已有仓位",与"以什么价格建仓"不是同一件事,
混在一起会把两个不同的量当成一个(V3 的教训:口径先分清再合并)。
⇒ 本单**只回答建仓侧**,SELL 侧另立。

## 4. ⭐定义检查(定义 vs 后果)

- **要测的东西**:一条事先定好的挑人规则,照它下注,**扣成本后、样本外仍然赚**。
- **卡门槛的变量**:被挑中的钱包在**没参与过排名的那段时间**里的配对价差(pp)。
- **它是定义本身吗?** ⚠️ **不完全是,这一点必须写明白**:
  配对价差衡量的是「**在同一个标的上,他比别人买得便宜多少**」。
  它**不等于**最终净收益,因为它不含"挑对市场"这一层
  (一个只在自己有把握的市场下注、但按公允价成交的钱包,在这里得分为 0)。
  ⇒ 本单测的是 **edge 的一个充分不必要条件**:
  **配对价差为正 ⇒ 在同标的上占了别人便宜 ⇒ 这部分是真钱**;
  但配对价差为 0 **不能**推出"没有 edge"。
  ⇒ 故本单的 🔴 **不构成对方向三的证伪**(§11 写死),只能砍掉"择时/择价"这一条路径。

## 6. 口径(与 V3 逐条相同,便于归因)

1. 只用已结算、`resolved_outcome` 非空的市场
2. 时间防火墙:`ts <= closed_time`(硬线)
3. 排除刷单市场(`wash_markets.json`)
4. `win = (outcome_index != resolved_outcome)` ⚠️ 与字面读法相反,已用末价独立验证
5. **只用 BUY**(见 §3.4)
6. 单元格门槛:该格内**除 w 之外**的成交数 ≥ **`MIN_OTHER_TRADES = 5`**
   (原写 `MIN_CELL_TRADES`,随 §3.4 留一法一并更正);钱包两窗各 **≥20 笔**
7. 主判决对象:按 D 窗得分排序的**前 10%** 钱包在 V 窗的得分,记 `R_V`

⚠️ 格里若没有别人的成交,就**没有可比对象**(不是"没本事")。
故设 `MIN_OTHER_TRADES` 下限,并**出声计数**被剔掉多少格、多少笔。

## 🔴 为什么我不认为这是找到了 edge(三条,全部实测)

### 1. 挑中的钱包是**往便宜档扎**的

V 窗平均买入价:前 10% **0.3133** vs 全体合格 **0.5221**(差 −0.2089)。
配对得分挑的就是"买得比同格别人便宜"的钱包 ⇒ 它系统性地选进低价区。

### 2. 而"真实盈亏"这把尺子在低价区**是坏的**

全体样本按买入价分档(V 窗):

| 买入价档 | 真实盈亏 | 赢家腿股数占比 |
|---|---|---|
| 0.00~0.05 | **+87.18%** | 2.07% |
| 0.05~0.15 | +17.25% | 11.53% |
| 0.15~0.35 | −1.06% | 25.65% |
| 0.35~0.65 | +3.80% | 52.07% |
| 0.65~0.85 | +4.48% | 76.89% |
| 0.85~0.95 | −0.12% | 89.78% |
| 0.95~1.01 | −0.32% | 98.19% |

**买 1 分钱的东西平均赚 87% —— 不可能是真的。**
机制:输的那条腿最后崩到 0 那一段我们**没采到**
(实测输家腿末价中位 **0.16**,而非 0.001,见 [[pitfall-lake-records-one-side-only]])
⇒ 数据里看到的低价买入,不成比例地是"后来涨回去"的那些。

⇒ **被挑中的钱包正好扎在这把尺子最坏的那一段。**

### 3. 更根本的:数据里只有**成交**,没有**挂单**

"买得比别人便宜"很可能描述的是**挂限价单被动成交**。
被动买单主要在价格**下行**时被打到(逆向选择),而未成交的挂单我们看不见。
⇒ 用只含成交的数据,**原理上**无法回答"这个价格优势能不能真的拿到手"。
这条不是数据量问题,是**数据种类**问题。

## 📌 结论(按预登记 §11 的措辞)

- 预登记红线上:**PASS**,不改。
- 但 §11 早已写死「PASS 仍不等于 edge」,本次三条实测把这句话具体化了。
- **可信的部分**:配对得分本身干净(全程不碰结算结果),且样本外持续
  ⇒「这批钱包确实持续地比同格其他人买得便宜」是一个**已验证的行为事实**。
- **不可信的部分**:它是否变成钱。因为验证这一步的尺子(真实盈亏)在低价区坏掉,
  而挑中的钱包恰在低价区。
